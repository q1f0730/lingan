## 拾穗 · Glean v0.32.0 — 同步 · 二：同一个 Wi-Fi 下手机电脑直连

上一版是经你自己的网盘同步；这一版不用网盘也行：Windows 电脑上打开 设置 → 局域网直连 → 在这台电脑上开启，电脑显示一个二维码，手机扫一下就连上。之后两台设备在同一个 Wi-Fi 下直接交换修改（穗、新枝、作品、套路墙、不要的理由、原图），不经过任何服务器，每次只传对方没有的那一点。同步也看得见了：上次什么时候、推了几行收了几行、哪几处两边都改过、哪台设备多久没来、为什么失败。云上（和电脑柜子里）的旧改动包也会在所有设备都确认过之后自动清理。

**下载**：安卓 `Glean_0.32.0_android.apk` · Windows `Glean_0.32.0_x64-setup.exe`（或 `.msi`）· Agent 桥 / 命令行 `glean-mcp.mjs` · 校验 `SHA256SUMS.txt`

**升级**：Windows 装着 v0.25 – v0.31 的会自动收到（更新前先自动备份）；安卓 v0.26 起可以在 设置 → 更新 里直接「下载并安装」。数据库不变（仍是 Dexie v12），不用迁移。安卓这一版多申请一个**相机**权限（只在你点「扫码连接电脑」时才会弹出询问）。

**做了哪些（编号见 docs/ideas/ideas.csv）**

局域网直连（ROADMAP「手机电脑同一片麦田」）
- **电脑是柜子，手机来取放**：Windows 版在本机开一个只存密文的小文件柜（默认端口 47322，被占了自动换），手机把它当成另一个同步后端。v0.31 的改动包 / 全库快照 / 内容寻址原图 / HLC 字段级合并原样复用，所以「两边各收 5 条 → 同步后两边都是 10 条、没有重复」「断开再连只传增量」和网盘同步是同一套保证
- **手机推来马上合并**：手机放进柜子的修改，电脑立刻合并；电脑自己的修改每分钟放进柜子一次，手机一来就能拿到
- **请求签名防同网偷看**：柜子里只有数据钥加密过的文件；每个请求都用数据钥派生的局域网钥做 HMAC-SHA256 签名（带时间和一次性随机串），同一个 Wi-Fi 里的别人截到请求也伪造不了、重放不了；时间用电脑的，两台设备时钟差一点也没关系
- **网盘 ↔ 局域网转发**：一台电脑同时开着网盘同步和局域网直连时，网盘那边来的修改会转给只连局域网的手机，反过来也一样
- **0645 二维码配对**：二维码里是电脑的局域网地址 + 一个 32 字节的一次性配对码（只经过摄像头，不走网络）；手机用配对码签名取一次「配对包」（里面是加密好的数据钥和电脑名字），取过就作废，10 分钟过期。二维码只认 192.168 / 10 / 172.16–31 / 127 这些局域网地址，被换成公网地址也不会往外发。扫码三条路：拾穗里开相机扫（安卓用 App 自带的 ZXing 识别，不需要 Google 服务）、从相册选二维码截图、用别的扫码工具扫出链接后粘贴

同步看得见
- **0564 同步记录**：设置 → 同步状态，最近 20 次同步一张无线表格（时间 / 方式 / 推 / 收 / 冲突 / 结果），失败的写原因、可以直接「重试」
- **0660 推 n 收 m、冲突 k**：每次同步说清推了几行、收了几行；冲突 = 两台设备在上次同步之后改了同一穗的同一处（按字段取较新的一边，旧值在「回到同步前」和操作快照里还能找回）。穗仓大标题旁一行小字「已同步 10:21」，上次失败时变成黑条并写原因，点一下去设置
- **0670 各设备**：每台设备每次同步后在云上（或柜子里）写一份加密的「回执」：名字、平台、版本、最后同步时间、合并到了别的设备第几包。设置里能看到所有设备，久不用的可以「移除」（它要是又来同步，会自动回到列表）

省请求、少占地方
- **云上旧改动包压缩清理**：每台设备只删自己的包，并且只删「已经写进自己的全库快照、而且列表里每台设备的回执都确认合并过」的那些；只有一台设备、或还有设备停在 v0.31（没回执）时不删。中间的包被清掉的设备下次同步会自动改读那台设备的全库快照补齐，结果和没清一样（单测：清理后回来的旧设备、全新设备都和源设备逐字段一致）。每写一次全库快照顺手清一次，也可以手动「清理旧包」
- **0659 坚果云限频适配**：429 / 503 / 502 / 504 按 Retry-After（最多 30 秒）或 1 / 2 / 4 秒退避重试；靠回执少发请求——某台设备的回执说它没推新包就不去列它的目录（每小时仍全列一次兜底），回执没变就不重新下载、自己的回执没变也不重写；新加入的空设备不再把刚拉下来的整库原样推回去
- **0663 每日一穗不同步**：daily 表不在同步表里（单测守住）

核对后标记（v0.31 已经做到，这次在总表里补标）：0523 WebDAV 同步、0542 同步包端到端加密、0643 原图按内容寻址、0675 改口令只重包数据钥。

**性能**：同一 InstaBox 会话交替 9 轮冷启动（画完首帧）v0.31 192ms / 4× 降速 588ms，v0.32 197ms / 589ms，持平；1000 穗搜索 ≤17.3ms、滚动 60fps 不掉帧。首屏 JS 558.4KB（+1.2KB，穗仓标题旁的同步小字），局域网 / 二维码代码全部懒加载（6.6KB + 4.1KB），安装包总资源 2238KB 仍在预算内。

**已知问题 / 没有真机验证**
- 局域网直连的电脑端只有 Windows 版（手机之间、手机当电脑那一端都不行）；网页版两端都不行（浏览器不能开服务，也不能从 https 页面访问局域网 http）
- 没在真机上跑过：Windows 防火墙第一次弹窗（要勾「专用网络」）、路由器开了「AP 隔离」的 Wi-Fi（设备之间互相访问不到，只能改用网盘同步）、vivo 上 WebView 相机权限和 ZXing 识别速度、电脑换 IP 后手机自动重连（现在要重新扫一次）
- e2e 里电脑柜子是按同一协议回应的 Node 参考服务（e2e/lanmock.mjs），Rust 柜子（src-tauri/src/lancore.rs）在本地单独编译后用同一套签名请求逐项核过（只追加 / 覆盖 / 列目录 / 取 / 删 / 路径穿越 / 重放 / 签名错 / 时间差 / 配对一次性），Windows 目标 cargo check 通过；安卓扫码桥（GleanQr.kt）本地 kotlinc 编译通过
- 还在用 v0.31 的设备不写回执，所以它们在的时候旧包不会被清理；升级到 v0.32 同步一次之后就会开始清
