## 拾穗 · Glean v0.35.0 — 认得出常用 App · 把旧仓库搬进来

这一版管「东西从别处进拾穗」：网易云 / QQ 音乐 / 豆瓣 / B 站 / 小红书 / 小宇宙的分享文案直接认出歌名、歌手、片名和类型；b23.tv、xhslink、163cn.tv 这类短链先跟着跳到真实地址再存；B 站视频带时间点的链接会在详情里写「从 3:12 看」；同一件作品又收了一次，可以「记一次重逢」而不是多出一穗；设置里多了「从别处搬进来」，豆瓣（豆伴导出）、flomo、浏览器书签、Kindle 标注、微信读书笔记、纯文本都能一次导进来，重复的不再收。

**下载**：安卓 `Glean_0.35.0_android.apk` · Windows `Glean_0.35.0_x64-setup.exe`（或 `.msi`）· Agent 桥 / 命令行 `glean-mcp.mjs` · 校验 `SHA256SUMS.txt`

**升级**：Windows 装着 v0.25 – v0.34 的会自动收到（更新前先自动备份）；安卓 v0.26 起可以在 设置 → 更新 里直接「下载并安装」。数据库不变（仍是 Dexie v12），不用迁移；穗多了一个不加索引的 `meets` 字段（重逢时间），随备份和同步走。

**做了哪些（编号见 docs/ideas/ideas.csv）**

认得出常用 App（ROADMAP v0.27）
- **分享文案直接认**：「分享某某的单曲《歌名》」（网易云 / QQ 音乐）→ 音乐穗，歌名 + 歌手；豆瓣、小宇宙、喜马拉雅取《》里的名字；B 站「【标题-哔哩哔哩】」去掉站名；小红书「标题 - 作者 | 小红书」拆出标题和作者。5 个平台各 3 条样例，14 / 15 认对（唯一认不出的是「某某发布了一篇小红书笔记」：这种文案里本来就没有标题，要联网抓）
- **0012 短链展开**：b23.tv、xhslink.com、v.douyin.com、163cn.tv、c.tb.cn、url.cn、t.cn、c6.y.qq.com 等先跟着跳转（最多 5 跳）拿到真实地址，存展开后、去掉追踪参数的链接（展开失败时保留原短链）
- **0803 B 站视频带时间点**：B 站视频走公开接口取标题、UP 主、封面、年份；链接里的 `t=192` 保留，详情的链接后面多一个「从 3:12 看」，点开从那一秒放。B 站视频算「电影」类
- **0062 播客链接**：小宇宙 / 喜马拉雅认得出来源和单集名，带时间点的同样显示「从 12:34 听」
- **0063 / 0064 平台识别**：网易云短链 163cn.tv、猫眼、TMDB、豆瓣移动版（m.douban.com/movie、/music）、手机版 B 站视频都能自动定类型（Spotify / Apple Music / YouTube Music / Letterboxd / IMDb 以前就认）

再次遇见
- **0016 记一次重逢**：同一件东西又收了一次（同链接、同图，音乐 / 电影按「作品名 + 作者」，带不带链接都算），提示条的按钮从「合并」变成「记一次重逢」：新写的为什么接在后面，不多出一穗。详情里写「首次拾于」和「重逢 n 次 · 最近 11/04」；在详情 / 待理里手动合并重复的穗也记一次重逢

把旧仓库搬进来（ROADMAP v0.28）
- **设置 → 备份与导入 →「从别处搬进来」**：选文件 → 在本机解析（不联网）→ 先看「新的几穗 · 已经有的几穗（跳过）· 读不出的几行」和前 5 条 → 先拍一张操作前快照再导入。导进来的直接进穗仓（不进待理），时间用原来的标记时间
- **0014 / 0802 豆瓣**：豆伴导出的 CSV 或 xlsx（每张表都读，「看过 / 想看 / 听过 / 读过」当标签），类型按条目链接定（电影 / 音乐 / 书 → 文案 + #书）；**0817** 短评进「为什么」，评分写进正文「我的评分 5」，打分日期当拾于。没有链接的通用 CSV（标题 / 内容 / 链接 / 时间 / 标签列）也能导
- **flomo**：导出的 HTML，每条 memo 一穗，`#标签`（含 `#灵感/子标签`）拿出来，时间照原样。100 条样例：条数、时间、标签一致，再导一次 0 条新的
- **浏览器书签**（Chrome / Edge 导出的 HTML）：所在文件夹当标签（书签栏 / 收藏夹栏不算），添加时间当拾于
- **0049 Kindle `My Clippings.txt`**（中文 / 英文）与**微信读书「导出笔记」**：每条划线一穗摘抄（书名 = 出处、作者、#摘抄、来自 Kindle / 微信读书）；微信读书的「想法 + 原文」→ 原文做正文、想法做为什么；Kindle 的书签条跳过
- **纯文本 / Markdown / 微信收藏导出的文字**：空行隔开的每一段一穗（只有链接 = 链接穗）
- **0065 导入报告穗束**：每次导进来的都放进一个穗束「导入 · 豆瓣 11/4」，导完提示收了几穗、跳过几穗已有的、几行读不出

顺带
- 拼音搜索的字表换成紧凑编码（GB2312 序号 + 变长数字，运行时用系统自带的 GBK 解码还原），31KB → 18.8KB，6763 个字的读音和以前逐字一致；省下的地方装下了这一版的新功能，总资源只比 v0.34 多约 2KB，没放宽体积预算

**性能**：同一 InstaBox 会话交替 9 轮冷启动（画完首帧）v0.34 201ms / 4× 降速 571ms，v0.35 190ms / 587ms，两项差异都在噪声内（Mann-Whitney 不显著），持平；完整 e2e：冷启动 171ms（4× 572ms）、1000 穗搜索 ≤17.2ms、滚动 60fps 不掉帧、备份 97.5MB 624ms。新代码都懒加载（导入解析 7.7KB 只在选文件时加载、平台解析 1.4KB 只在抓链接时加载）；首屏 JS 565.3KB（+2KB：分享文案规则、查重、重逢），总资源 2219.7KB。

**已知问题 / 没有真机验证**
- 短链展开和 B 站接口在 App 里（经 Rust 发请求）才生效；网页版会被浏览器跨域拦下，退回只用分享文案里的标题、保留原短链。e2e 里 B 站接口用模拟回应测，短链跳转（拿最终地址）由单测用假请求测——Playwright 拦不到 302 之后那一跳
- 分享文案的样例是照常见格式手写的，不是从真机复制的；各 App 改了文案格式就可能认不出（照样存成链接穗，联网后补标题）
- 没真机试过：豆伴最新版导出的 xlsx 实际列名（按表头关键字认，列名对不上会算「读不出」）、flomo 新版导出的 HTML 结构、Kindle 日文 / 繁体格式
- flomo 导出里的图片、微信收藏里的图片 / 文件不导（只导文字）
- 还没做：0015 / 0801 网易云歌单整单拾进（要调网易云接口和登录）、0013 公众号正文快照、0804 RSS 进待拾
