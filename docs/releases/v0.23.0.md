## 拾穗 · Glean v0.23.0 — 待理与补为什么

上一版让「收」快到 1 秒；这一版管「收完以后」：刚收的先放进「待理」，穗仓只留理过的；没写为什么的集中在一处，一次补 5 条；顺手把重复、乱标签、一条条点开整理这些麻烦一起解决。

**下载**：安卓 `Glean_0.23.0_android.apk` · Windows `Glean_0.23.0_x64-setup.exe`（或 `.msi`）

**升级**：直接覆盖安装（安卓签名与 v0.20 起相同的新密钥 + 轮换证明）。数据库升到 **Dexie v9**：穗加两个索引 `inbox`（待理）和 `*dup`（重复钥匙）。迁移只补重复钥匙（按链接 / 文字算），**老穗一律不进待理**，不改任何内容；老原图的哈希不在启动时算，等你这次打开后第一次收进一张图时才补一遍（升级后第一次收图的「收过了」提示会晚一两秒）。v1–v8 每一版的夹具库都有升级回归测试。

**做了哪些（13 条 + ROADMAP 2 项，编号见 docs/ideas/ideas.csv）**
- **0101 待理收件箱**：速记栏、速记小窗、剪贴板「拾进来」、安卓分享 / 极速拾 / 选字 / 磁贴 / 常驻通知 / 正在播放收进来的穗，先进「待理」；穗仓只显示整理过的，和在待理里超过 7 天的。穗仓顶上一条「待理 (n) · 去整理」；待理页每穗三个动作：留下 / 补一句 / 丢掉（都可撤销），右上「全部入仓」一键清空（可撤销）。「展开速记」里填好再存的、编辑过的穗算整理过，直接进穗仓。设置 → 待理与标签里可以关掉待理（关掉时现有的待理穗一起进穗仓）
- **0115 三秒整理**：待理页「三秒整理」一次一穗：桌面键盘 `1` 留下 · `2` 补一句（焦点直接进输入框，回车存）· `3` 丢掉 · `→` 稍后，`Esc` 退出；手机右滑留下、左滑丢掉。顶上写「今天理了 n 穗」（本机按天计）
- **0102「缺为什么」专栏**：穗仓顶上「缺为什么 (n) · 补 5 条」，进去一次给 5 条没写为什么的穗（最近收的在前，示例不算），输入框就在列表里，回车就存；「跳过」把这条放到最后，「换 5 条」整批换
- **0146 提示问题，不替你写**：补写框下按类型轮换 3 个问题（电影：哪个镜头还记得？哪句台词？…），点一下把半句开头放进输入框，接着写；全是本地文案，不调模型
- **0160 整理度**：口味页新增「整理度」——写了为什么 n / 总数、有标签 n / 总数、还在待理 n，都是真实计数；点「写了为什么」直接进缺为什么专栏
- **ROADMAP v0.31 这穗收过了**：收的时候按三把钥匙查重——同一个链接（去掉 utm / spm / share / from 等追踪参数、www / m 子域、末尾斜杠）、同一张图（原图 SHA-256）、几乎一样的文字（忽略标点、空格、全半角、大小写）。查到就轻提示「这穗 10/19 收过了（同一个链接）· 合并」，不理它就是仍然保存；待理卡片和详情页也会显示，可「合并进它」
- **0126 合并不丢东西**：合并 = 留下旧的那件，标签取并集，两次的为什么都留下（用 / 隔开），时间取更早，旧穗缺的作者 / 年份 / 正文 / 来源用新的补上；新的那件进回收站，合并可撤销
- **ROADMAP v0.40 一次整理一把 + 0159 连选**：穗仓「选择」进入多选（网格 / 列表 / 时间线都行）：点选、`Shift` 点连选一段、`Ctrl+A` 全选当前筛选结果、`Esc` 退出；底部工具条批量 加标签 · 改类型 · 入仓（出待理）· 带进嫁接 · 删除，每个都可撤销（删除进回收站）
- **0103 标签别名与合并**：设置 → 待理与标签列出全部标签和计数，点选几个合并成一个：旧穗自动改写，并记成别名（以后再输入「夜晚」「night」自动写成「夜」）；别名可以单独去掉
- **0147 标签体检**：同一处列出写法很近的标签（夜 / 夜晚、Neon / neon，一键合并）、只用过一次的、半年没用的
- **0148 共现推荐**：详情页标签后面「常一起：+城市 +蓝」，待理卡片上「加标签」——都来自你自己的历史（至少一起出现过 2 次），点一下加上
- **0110 AI 标签只从你的词汇里选**：看图整理时把你已有的标签表给模型，只从里面选；实在要新词，显示成虚线的「新：窗？」，点一下才加进标签，✕ 不要。「氛围感」「治愈」这类泛词和套路墙上的词直接丢掉
- **0111 搜索语法**：`type:电影` `tag:夜` `year:199x` `from:小红书` `why:空` `before:2026-10` `after:2026-09` `inbox:是` 可以叠加，前面加 `-` 是排除，中文冒号也认，值里有空格用引号；剩下的字照常全文搜。输入 `tag:` 时下面给补全，搜索页空着时列出全部写法，点一下插入
- **0113 详情上一穗 / 下一穗**：按打开时那个视图的顺序翻（穗仓的筛选、搜索结果都算）：顶上「← 上一穗 · 3 / 15 · 下一穗 →」，桌面 `←` / `→`，手机左右滑

**v0.22 已知问题：极速拾要等打开 App 才入库 → 部分解决**
- 原生侧没办法直接写 IndexedDB（它在 WebView 自己的存储里，安卓没有对外接口），所以「完全不打开 App 就入库」做不到
- 改成了**后台同步**：只要拾穗主界面还在后台活着（没被系统杀掉），半屏面板 / 磁贴 / 常驻通知 / 小部件一存，原生就叫 WebView 立刻把这一条收进库（进待理），不用等你切回来。主界面已经被系统回收时，仍按 v0.22 的方式下次打开时收

**性能**（InstaBox e2e，1000 穗含 300 张图，数字见 docs/perf/v0.23.0.json）
- 冷启动（同一会话与 v0.22 交替测，中位数）：普通速度基本持平（三组 206 vs 206、192 vs 198、220 vs 230ms）；**CPU 降速 4 倍慢 2–7%**（577 vs 618、581 vs 598、678 vs 689ms，约多 11–41ms）。最终构建完整 e2e 单测一次：冷启动 218ms、4× 655ms
- 瘦了首包：搜索、待理、缺为什么、多选工具条、整理函数（organize）、批量操作（batch）都改成点开才加载（穗仓画完后空闲时预取，点开不等）；首屏 JS 由 v0.23 初版的 563KB 降到 546KB（v0.22 为 523KB + 7 个小块），并且首屏只剩一个 app 块（库层 db / Dexie 在里面，没被拆成单独的首屏块）。同会话三方交替测：瘦身前 614ms、瘦身后 618ms、v0.22 577ms——**瘦首包没有换来可测的提速**，4× 下多出的那点时间更像是运行时（v9 每穗多了重复钥匙、穗仓多算待理 / 缺为什么计数），不是包大小，留到下一版查
- 查重走 `*dup` 多值索引，收一穗只按 2–3 把钥匙查，不扫整表；老原图补哈希只在收进图片时才跑（启动、滚动、备份时都不读原图）
- 搜索 1000 穗断网：输入到结果画出 ≤17.4ms（4× ≤40.7ms）；滚动：网格 / 时间线 / 列表 60fps 掉帧 0%；备份 97.5MB 图 → .glean 665ms
- 字体沿用 v0.21 的切片（本版新界面字全在常用字切片里；唯一一个切片外的「帧」改了措辞）

**已知问题**
- 低端机（4× 降速模拟）冷启动比 v0.22 慢 2–7%（几十毫秒），瘦首包没解决，原因待查
- e2e 里「导出备份时 JS 堆增长 ≤48MB」这条阈值在 InstaBox 上波动大（同一构建 38–51MB，v0.22 时也有 41.6MB），偶尔要重跑
- 后台同步依赖主界面 WebView 还活着：vivo / OriginOS 这类省电激进的系统常在后台几分钟后回收进程，这时仍要等下次打开才入库（真机未测）
- 合并时两次的为什么拼成一段（用 / 隔开），还不是分开的两条记录
- 搜索语法里的筛选只对穗生效，用了语法就不列新枝
- 别名表存在本机（localStorage），不进 .glean 备份；换设备要重新合并一次
- 待理开关同样只存本机
