## 拾穗 · Glean v0.30.0 — 嫁接 · 人在环里

这一版让你在嫁接的每一步都能插手：长之前翻一张斜策略卡、掷一条硬约束、开「野一点」；第一步找出的张力先给你勾，再往下长；新枝长出来之后能追问「这个怎么拍 / 开头怎么写」、能再嫁接出子枝、能记下「做了吗」。口味页多了「我在意的东西」（口味原子），能一键复制成提示词贴进别的 AI；秒搜里可以直接问穗仓。每次发给模型的东西，发之前可以先看一眼，设置里能看到本月发出去了什么。没有 AI key 时这些都有离线版本。

**下载**：安卓 `Glean_0.30.0_android.apk` · Windows `Glean_0.30.0_x64-setup.exe`（或 `.msi`）· Agent 桥 / 命令行 `glean-mcp.mjs` · 校验 `SHA256SUMS.txt`

**升级**：Windows 装着 v0.25 – v0.29 的会自动收到（更新前先自动备份）；安卓 v0.26 起可以在 设置 → 更新 里直接「下载并安装」。数据库仍是 **Dexie v11**，不改表结构：新枝上新增的字段（约束、落地状态、追问、父枝）都是可选字段，旧数据原样可读。

**做了哪些（10 条编号 + ROADMAP 三项，编号见 docs/ideas/ideas.csv）**

嫁接前：约束台
- **ROADMAP v0.23 斜策略卡 · 野一点**：嫁接页「这次的约束」翻一张斜策略卡，可重抽、可钉住、可写自己的卡（自己写的进牌堆，撞套路墙的卡跳过）；钉住的卡写进这次新枝的「用了什么约束」。「野一点」开关：第一步请求温度临时提到 1.5，并加一条「先打破这组穗默认的一个前提」的指令；关掉回到设置里的温度
- **0216 约束骰子**：掷一条硬约束（60 条，分通用 / 影像 / 声音 / 文字 / 视觉五组，写了方向就优先那组；同一天第一次掷到的是同一条，重掷不重复上一条），写进 prompt 的 CONSTRAINT 段，并显示在新枝卡上
- **0201 张力手选**：打开「先挑张力再长」，第一步（MAP）找出的 4 个张力先停下来给你勾 1–2 条，第二步只沿着这几条撒种子；也可以「都要，直接长」
- **0207 大众答案对照**：第一步多要一句「大众版」（大多数人拿到这组素材最顺手会做的东西，不展示，只在溯源里看得到）；三根新枝里离它太近的会被换成替补，替补也不行就留着并如实标出来

新枝之后
- **ROADMAP v0.24 新枝再嫁接**：每根新枝下「更野 / 更能落地 / 换一种形式」（歌 → 短片 → 海报 → 文案 → 装置 → 游戏 → 播客 → 一组照片），子枝挂在原枝下面，溯源仍点得回原来的穗；新枝页按树显示。离线三种都能出
- **0204 新枝追问**：新枝下一行输入框问「这个怎么拍 / 开头怎么写」，回答只引用这一批穗（按真实 ID 校验，[#ID] 换成穗名）；没连模型时给一个能马上动手的离线路子。每根最多留 20 条
- **0904 做了吗**：新枝状态 种子 / 试过 / 做成 / 放弃，新枝页可按状态筛；「附一张结果图」把小实验的结果收成一穗（带标签和来历），形成闭环

口味
- **0205 口味原子**：口味页「我在意的东西」——从你写的「为什么」里抽出 ≤20 个审美判断（手写感、留白、低保真…）；有模型时 AI 抽（引用只认真实穗），没有就离线按反复出现的短语（≥2 穗）。可改、可删、可自己加（自己加的排前面）；嫁接时带上前 8 个，新枝至少要接住其中一个
- **0244 口味导出卡**：「复制为提示词」生成 ≤300 字的 Markdown，只含原子与代表作，不含私密穗、不含「为什么」原文，署名 Q1f730，可以贴进任何 AI 当 system prompt

对话
- **0211 问穗仓**：秒搜里点「问穗仓」，问一句「我收过哪些关于灯的东西」：先在本地按字面找出最相关的 20 穗，再只基于这些穗回答，每句带穗；没连模型就直接列出来；一穗都没找到就直说没有，不调模型
- **0237 收成穗**：有用的回答一键「收成穗」（想法穗，来源记为穗仓对话，内容是这一问一答）

隐私
- **ROADMAP v0.25 发出去前看一眼**：设置 → 出站「调模型前，发出去前看一眼」：不看 / 只看一次 / 每次。弹出的纸片里就是这次真实的请求体全文（发给谁、用什么模型、温度、字数）；图片像素默认不上传，要勾选才带上；点「不发了」就不发
- **0906 出站清单**：同一面板「本月发出去了什么」：按域名汇总次数和发了哪几类（文字 / 图片 / 链接）、大小，看最近 20 次；只记域名、种类、字段类别和字节数，不记内容、不记密钥，只存在本机

**修复**
- **草稿编辑区不再露出 uid**（v0.29 已知问题）：编辑框里只显示 `[[标题]]`，底层画成一块引用 chip，草稿里照样存 `[[标题|uid]]`；退格碰到引用整块删、在引用中间打字落到引用后面、粘贴带 uid 的完整引用会自动收起
- 草稿里打 `[[` 选穗：打字快、弹窗还没跟上最后几个字时按回车，会按框里现在的字重新挑，不再插进旧列表的第一穗（慢机器上能复现）
- 新枝「立项」后偶尔停在作品列表、没直接打开那件作品（慢机器上首次进作品页的渲染被丢弃重来时读不到要打开哪件）
- 追问的离线回答结尾不再出现「。。」；挑张力时一条没勾，按钮写「先勾 1–2 条」，不再是「沿这  条长」

**冷启动：v0.29 慢在哪、怎么修的**
- v0.29 的发布说明里记着「普通冷启动比 v0.28 慢约 12ms、原因未定位」。这一版用 profile 查清楚：穗仓的「全部穗」查询以前在 Library 的 useEffect 里才订阅，而 useEffect 要等外壳第一帧画完才跑，于是「读库」排在「画空外壳」后面串行（读库开始比 Library 第一次渲染晚 60–100ms），这段等待对页面上任何多出来的东西都很敏感，v0.29 多出的导航项 / 新表定义就够把它推慢一点
- 修法（src/lib/libitems.ts）：main.tsx 在 root.render 之前就开查，读库和下载 / 解析外壳并行；结果 300ms 内到就等它再画，第一帧直接带卡片（省掉「空外壳布局 + 绘制一遍、卡片再来一遍」）；库很大 / 读得慢就照旧先画外壳。Library 用 useSyncExternalStore 读同一个 liveQuery 订阅，库变了照常实时刷新，不会查两遍；离开穗仓或 5 秒没人接就退订清掉，不拿旧结果
