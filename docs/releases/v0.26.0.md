## 拾穗 · Glean v0.26.0 — 数据保险与安全更新

这一版不加新玩法，专门让穗丢不了：Windows 和安卓每天自动备份一份完整的 .glean，写完立刻回读核对；导入、清空、批量删、清空回收站之前都先拍一张快照，点一下就能回到那之前；装新版前先自动备份，数据库要升级前再存一份原样副本；存储写满时新穗先暂存，下次打开自动补上。安卓从这版起能在 App 里直接下载并安装新版。

**下载**：安卓 `Glean_0.26.0_android.apk` · Windows `Glean_0.26.0_x64-setup.exe`（或 `.msi`）· Agent 桥 / 命令行 `glean-mcp.mjs` · 校验 `SHA256SUMS.txt`

**升级**：Windows 装着 v0.25 的会自动收到这一版（设置 → 更新，或启动后提示「重启更新」）；这一次是 v0.25 的旧代码在装，所以还不会先备份——升级前想稳妥就先手动「导出备份」，从 v0.26 往后的更新都会先自动备份。安卓这次还得手动装一次 v0.26.0（签名与 v0.20 起相同的新密钥 9771c62b… + 轮换证明），之后的版本可以在 App 里直接装。数据库**不变（仍是 Dexie v10）**，没有迁移。

**做了哪些（12 条，编号见 docs/ideas/ideas.csv）**

自动备份（D1 / C2）
- **0606 自动本地备份 + GFS 轮转**：每天第一次打开后（启动 20 秒、空闲时）把整个穗仓（穗、新枝、套路墙、原图原样二进制）写成一份 .glean，和手动导出同一种格式，任何设备都能导入。库和上次备份时一样就跳过，不浪费空间。保留：最近 7 天每天一份、4 周每周一份、12 个月每月一份；也可以选「最近 7 份」
- **0508 每天备份到本机文件夹**：Windows 默认「文档\Glean\backup」；安卓写进「下载/Glean」（Android 10+ 走 MediaStore，卸载 App 文件也还在，不需要存储权限；Android 9 退回 App 专属目录）
- **0609 备份位置可选**：Windows 上「换文件夹…」可以选坚果云 / OneDrive 的同步文件夹，备份自动上云；选过的文件夹重启后照样能写（tauri-plugin-persisted-scope）。可以「改回默认」
- **0637 写完立刻回读校验**：每份备份写完马上按 manifest 重新读一遍：每个文件的大小、sha256、data.jsonl 行数都对上才标「已验证」，否则标「损坏」并提示；校验没过的那份不会去顶掉旧的好备份。设置 → 自动备份 里列出每份（时间、种类、大小、已验证 / 损坏），「恢复…」直接进导入预览（合并 / 只补缺 / 替换）

操作前快照（D1）
- **0621 大操作前自动全库快照**：导入（三种模式）、清掉示例、清空、一次删 2 穗以上、彻底删、清空回收站之前，自动拍一张快照（存在另一个本机数据库里，和主库分开）；会真删原图的操作连那几张原图一起存。设置 → 操作前快照：「回到这之前」一键恢复（恢复前先给现在再拍一张，随时能反悔），留最近 10 张
- **0622 清空先导出**：「清空」现在先把整个穗仓导出成 .glean（存好了才往下走，取消或失败就什么都不删），再确认一次，再拍快照，最后才清
- **0624 数据库升级前存原样副本**：装了新版、本机数据库要升级时，先按旧版本原样读出所有穗 / 新枝 / 套路墙存一份（留 3 份），再升级。平常启动不碰数据库，没有任何额外开销

安全更新（C2）
- **0513 更新前自动备份，迁移失败可回滚**：Windows「重启更新」、安卓「下载并安装」之前，都先写一份完整备份到备份文件夹（不参与轮转，留最近 3 份），备份失败会问你要不要照样更新。新版打开时数据库若升级失败，IndexedDB 整体回滚仍是旧库，兜底页能导出；成功但数据不对，用升级前副本（存成文件后「导入备份」）或更新前的 .glean 恢复
- **0750 更新说明**：发版时把这份说明压成几行写进 latest.json，设置 → 更新 里有新版时显示「这版新了什么」
- **0512 安卓应用内下载安装**（+ 0732 重复项）：设置 → 更新 → 「下载并安装」：App 里直接下载新 APK，边下边算 SHA-256，必须和 Release 里 SHA256SUMS.txt 一致；再核对新包的签名证书和当前装着的拾穗一致（含轮换历史）；然后自动备份，再交给系统安装器覆盖安装。第一次会让你允许「安装未知应用」。新版发布中（校验文件还没出来）会提示过几分钟再试

可靠性（D1）
- **0605 写入失败兜底**：新穗写不进数据库（空间满、事务被中止、库被关掉）时，不丢：文字、链接、标签（原图不超过约 1.2MB 时连图）暂存进本机待写队列，提示「已暂存，下次打开自动补进穗仓」，输入框照常清空；下次打开（或空间腾出来后）按原来的时间和 uid 补进库，重复补也只算一次

**修复 / 工程**
- 查清 v0.25 的 e2e「导出堆增长 ≤48MB」偶发超标：同一会话交替测 v0.24 / v0.25 各 12 次，导出堆峰值 v0.24 中位 36.4MB、v0.25 中位 42.9MB（Mann-Whitney U=114/144，p≈0.02），两边都有单次 55–64MB 的离群值。结论：GC 时机抖动为主 + 一个约 5MB 的小回归——导出进度每变一次整页设置都重画，v0.25 多了 Agent / 更新两块面板。修：设置页里与进度无关的面板全部 memo；测量改稳：同一页连续导出 3 次、每次前强制 GC，取中位数和 48MB 比（阈值不变，三次都记进 perf.json）

**性能**（数字见 docs/perf/v0.26.0.json）
- 冷启动（InstaBox 同一会话交替测 7 轮，1000 穗 / 300 图，中位数）：**v0.25 197 / 580ms（4× 降速）、v0.26 181 / 575ms**，没有退化。首屏只多了写入兜底与升级检查两段小代码（平常启动不碰数据库）；自动备份、快照代码都是懒加载，自动备份在启动 20 秒后、空闲时才加载
- 单独跑（e2e perf）：冷启动 195ms，4× 657ms；旧库首次打开 + 迁移（含存升级前副本）1713ms；搜索 1000 穗断网最慢 18.9ms（4× ≤41ms）；网格 / 时间线 / 列表滚动 60fps 掉帧 0%；备份 1000 穗 / 300 图（97.5MB）→ .glean 710ms，导出堆增长三次中位 +16.2MB，新设备导入堆 +33.4MB
- 首屏 JS 543.8KB（gzip 182.9KB，比 v0.25 多 3.9KB），首屏 CSS 117.1KB，都在预算内

**没做 / 已知问题**
- 网页版没有本机文件夹：自动备份只在 Windows 和安卓上有（网页版有操作前快照，备份请手动「导出备份」）
- 快照只存在本机（和主库同一个浏览器存储里）：防的是误操作和升级出错，不防手机丢了 / 清除应用数据——那要靠自动备份文件或导出
- 升级前副本不含原图（迁移不动原图表）；回收站 30 天到期的自动清理不拍快照
- 安卓自动备份只能写「下载/Glean」，还不能选别的文件夹（SAF 目录授权是 0640，留到之后）
- 备份没有口令加密（0638 / 0932 留到之后）；国内更新镜像（0548 / 0731）仍没做
- 没在真机上验证：安卓应用内安装（OriginOS 的「安装未知应用」授权路径、MediaStore 写「下载/Glean」）、Windows 自定义文件夹重启后的权限保持、v0.25 → v0.26 的 Windows 自动更新完整一轮（latest.json 已按 v0.25 updater 的解析规则核对过）
