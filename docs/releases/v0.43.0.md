## 拾穗 · Glean v0.43.0 — 存得干净 · 存得稳

这一版管两件事：照片里不该带的东西别带走，数据该备份的时候提醒你。从别的 App 分享进来的照片，收进来时会抹掉里面的位置（GPS），拍摄时间留下来——详情里多了一个「用拍摄时间」，一点就把「拾于」改成照片真正拍下的那天；太大的原图会缩到长边 4096。图要离开这台设备（发给看图模型、导出到 Obsidian）之前，EXIF / GPS / 相机型号都会去掉，只留方向。设置 →「备份与导入」里能看到上次备份是几天前、占了多少空间；超过 14 天没备份，打开后会轻轻提一句。导入备份前能看到这份备份拾于哪段时间、和本机重叠多少穗。嫁接配方和智能穗束也跟着备份走了。

**下载**：安卓 `Glean_0.43.0_android.apk` · Windows `Glean_0.43.0_x64-setup.exe`（或 `.msi`）· 浏览器扩展 `glean-extension.zip` · Agent 桥 / 命令行 `glean-mcp.mjs` · 校验 `SHA256SUMS.txt`

**升级**：Windows 装着 v0.25 – v0.42 的会自动收到（更新前先自动备份）；安卓 v0.26 起可以在 设置 → 更新 里直接「下载并安装」。数据库不变（仍是 Dexie v12），不用迁移；穗多了一个不加索引的字段「拍摄时间」，随同步走。

**做了哪些（编号见 docs/ideas/ideas.csv）**

照片
- **0651 收图抹掉位置、留下拍摄时间**：新收的图（分享 / 极速拾 / 表单 / 拖进来）做缩略图时顺手处理：JPEG 里 EXIF 的 GPS 目录连同坐标数值原地清零、XMP 整段去掉，PNG / WebP 的 EXIF / XMP 块去掉；读出拍摄时间（带时区就按时区）存成「拍摄时间」。和「拾于」相差一天以上时，详情的「拾于」下面出现「用拍摄时间 2024/03/02」，点了就改。备份导入、同步拉下来的图不动（那是你自己的数据）
- **0636 大照片缩到长边 4096**：别的 App 分享进来的原图长边超过 4096 时重存成 JPEG（质量 0.9，方向已转正），长截图 / 全景不缩（短边不压到 1080 以下）；重存后反而更大就留原图。设置 → 极速采集 可以关掉（保留完全原图）。表单 / 速记选的图本来就缩到 1280，不受影响
- **0650 图离开本机前去掉拍摄信息**：发给看图模型、导出到 Obsidian 时，去掉全部 EXIF / XMP / IPTC（位置、时间、相机型号），只留一个方向标记，竖拍的图不会躺着；设置 → 极速采集 可以关。.glean 备份仍是原样（备份是你自己的）

备份与空间
- **0639「上次备份 n 天前」**：设置 →「备份与导入」显示上次备份（手动导出 / 自动备份）；超过 14 天没备份、穗 ≥20 时，打开拾穗约 18 秒后提一句「上次备份是 n 天前」，点「去备份」直达设置；7 天内只提一次，可以关
- **0631 存储用量**：同一处显示已用 / 可用（浏览器 / WebView 给的估计）和占比，没持久保存时可以「申请持久保存」；超过 80% 标红并在启动后提醒一次（3 天内不重复），告诉你先导出备份、清回收站、或打开缩图
- **0641 恢复前预览**：选好备份文件后、写库之前，多一行「拾于 2024.3 – 2026.11 · 和本机重叠 120 穗 · 配方 2 · 智能穗束 3」（原来就有条数、图数、三种方式各会怎样）
- **嫁接配方 / 智能穗束进备份（v0.42 遗留）**：.glean 备份和操作前快照都带上；合并 = 本机的为准、补上备份里没有的；旧备份里没有这两样时，合并和替换都不动本机的。同步仍只在本机（下一步）

隐私与工程
- **0935 隐私承诺写成可测试的条款**：新增 docs/PRIVACY.md，12 条承诺每条指向一个自动测试（新装逛一遍各页不发任何外部请求、密钥只进钥匙串、私密 / 上锁 / 出口开关、分享卡不带为什么、同步端到端加密、照片去 GPS……）；单测逐条核对这些测试真实存在，删测试或改名 CI 就失败。e2e 新增「新装打开、逛遍各页，没有一个非本机请求」
- **0653 identifier 不可改**：tauri.conf.json 的 com.q1f730.lingan 写进发版手册禁忌和 AGENTS.md，preflight 和单测都会拦

修复
- **速记表单恢复草稿不再先闪空表单**：上次没存的表单草稿改在表单第一次画出来时就填好（原来先画一帧空表单、稍后才填上，手机忙的时候能看到空表单，刚好这时动手还可能把草稿盖掉）
- **测量更稳（开发者向）**：导出大备份的堆增长门由 3 次取中位改为 5 次取中位，阈值仍是 48MB；v0.42 / v0.43 同会话交替各 9 轮，导出代码与 v0.42 逐字节相同、堆增长中位数 34.0 / 33.1MB，确认 v0.43 整套里那次 56.3MB 是 GC 时机的噪声

瘦身（预算不放宽）
- 同步口令用的 Argon2id（hash-wasm）里的两段 wasm 原来是原样 base64：构建时改成 deflate 压缩、加载时用浏览器自带的 DecompressionStream 解开（wasm 字节不变，单测逐字节核对），总资源少 11KB，腾给这一版

**核对后标为已做的重复项**：0933 链接追踪参数清洗、0526 分享文案口令清洗（v0.28 的 0023 / 0019 已做）、0634 速记草稿自动保存（v0.22 的 0025 + v0.39 的立即写已做）。

**还没真机验证**：安卓分享进来的大照片缩图速度、vivo 相册原图的 EXIF 写法；各 WebView 给的存储用量估计差别很大，只当参考。
