## 拾穗 · Glean v0.13.0 — 千穗不卡

*A thousand ears, no stutter.* 穗仓攒到一千穗、三百张照片，打开照样快，往下划照样顺。界面样子不变，变的是底下怎么存、怎么画。

**下载**：安卓 `Glean_0.13.0_android.apk` · Windows `Glean_0.13.0_x64-setup.exe`（或 `.msi`）

**变快了什么**
- 原图和缩略图分开存：每张图另做一张约 12KB 的小缩略图放在列表里，原图（约 300KB）单独放一张表，只有点开详情、编辑、让 AI 看图、导出备份时才读
- 穗仓（双列 / 三列瀑布）和时间线都改成虚拟滚动：一千穗也只挂着屏幕上下附近的二十来张卡片
- 图片懒加载：卡片滚到附近才去读缩略图，滚出去就释放内存（objectURL 回收）
- ASCII 显影同时最多两张，快速滑动时其余直接显示照片，不再一屏十几个动画一起跑

**实测（e2e 自动化，1000 穗含 300 张 1280 边照片，手机尺寸 390×844 @2x）**

| 项目 | 普通 | CPU 降速 4 倍（模拟中端安卓） |
|---|---|---|
| 冷启动到穗仓画出首屏 | 195 ms | 569 ms |
| 首屏缩略图全部解码完 | 225 ms | 642 ms |
| 穗仓瀑布快速滑动 | 60 fps，掉帧 0% | 60 fps，掉帧 0% |
| 时间线快速滑动 | 60 fps，掉帧 0% | — |
| 同时挂载的卡片 | ≤ 20 张（共 1000） | ≤ 21 张 |

- 缩略图平均 11.8KB（最大 12.5KB），原图平均 333KB
- 从旧版升级的第一次打开（含数据库迁移）1.9 秒出首屏；300 张缩略图在后台约 7 秒补完，期间卡片先用原图顶着，不空白
- e2e 里有断言：冷启动（普通和 4 倍降速）都必须 ≤ 2 秒、掉帧 ≤ 10%、卡片不能叠在一起、objectURL 不泄漏、详情显示原图而卡片只用缩略图

**升级说明**
- 数据库升级到第 3 版，自动迁移：旧穗里的图片原样搬进单独的原图表（一字节不丢），之后在后台空闲时慢慢补缩略图，不卡首屏
- 导出的备份格式不变（图片仍是完整原图），v0.12 及更早的备份照常能导入
- 穗不多（60 张以内）时不启用虚拟滚动，所有卡片都在

**小变化**
- 瀑布改为「哪列短放哪列」的排法，最新的几穗横排在最上面（以前是先排满第一列）
- GIF 在列表里显示为静态缩略图，点开详情仍会动
